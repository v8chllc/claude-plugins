# Shared code review and findings policy

All three orchestrators apply this contract to every participating pull request. The resolved review capability owns its procedure; the manager triggers it and records the per-repository invocation budget. Inner review-and-fix cycles count within their parent review invocation. A lower repository cap binds first, and an extra invocation requires the existing authorization. Nothing here enlarges a budget.

Account for every in-bound finding across reviewed heads. A quiet incremental review does not settle an earlier finding. Each ends as `fixed`; `declined` only when a reproduction shows that the finding is wrong; `deferred` with a work-item record; or escalated to the sponsor with an `orchestration-decision` marker. An advisory `fix_requested` decision is provisional until the retained builder returns the fix. A tool-generated addressed mark is evidence for a fix, never its disposition. A deferral with no filed issue is expected: an authorized supervisor may file a corroborated Backlog follow-up separately, or the sponsor handles it when no supervisor is present. The manager and builder do not create deferred issues.

Safety, privacy, authorization, and test findings cannot be declined. A finding identifying a class of defect prompts an audit for other instances beyond the diff, with the result recorded. A late finding reopens triage. A fix that changes the head needs review of the new head and renewed assessment of affected evidence.

The manager checks every review fix against the accepted plan: a fix that removes something the plan requires is reverted by the retained builder and reported. A fix that adds scope the plan does not include is reverted by the builder before the next review invocation, or before verification when none remains. Report it as a `material` deviation and add the gap the fix answered to the canonical `deferred` list. Keeping the addition instead requires sponsor approval of a revised plan. For chore, the issue-defined scope serves as the plan in these checks, and a changed scope requires a sponsor issue edit. Consensus review uses its own fixer during the invocation.

A review is clean only when it completed at the current head and every in-bound finding from every review on that pull request has a disposition. A review pass that fixes anything creates a new head and needs another review. The orchestrator never copies a report or synthesizes review text; the review capability authors it.
